Roll your own: Export a style, change its id and name, rearrange its sections, then Import. Import also takes a whole Export all list — one paste copies a set of styles to another keyboard. ["row",…]
A row of round buttons. "|" spaces it out.
["dpad"]
The arrow cluster.
["ring"]
The same five keys as a round nav ring. ["ring",{"size":200,"center":96}] sizes the ring and its centre button.
["strip",…]
Labelled columns side by side: ["strip",["Vol","volume_up","volume_down"],…]
["rocker",…]
The same groups as one-piece rocker keys. ["","mute"] is a single key of the same height.
["media",…]
A row of small transport buttons.
["apps",…]
A row of wide pills.
["grid",…]
Equal rectangles in columns, the layout said once: ["grid",{"cols":2,"h":56,"opts":"sq"},["spare1","Copy"],["spare2","Paste"]]. The settings are optional — cols 1–8 (2 if left out), h 24–160 pixels, and opts every key takes. A key's own options add to those, and "|" leaves a cell empty.
["lcd",…]
A small screen: ["lcd",["Room","temp"],["Host","@host"]]. Each line is a label and the value to show — @host @slot @mac @state @rssi @battery @layout come from the keyboard itself, @last and @station name the button just pressed, @msg shows what an lcd:text action wrote, and any other name is an entry in the component's sources:. A third entry sizes and justifies one line: sm lg xl, left centre right, or a #hex colour. Left alone a line spreads — label one side, value the other. A settings object in front of the lines sizes the panel itself like a real display: {"cols":16,"rows":2} is 16 characters by 2 lines (4–40 and 1–8), and fg bg label border colour that panel alone.
["-"]
A divider.
"theme"
Size and colour, e.g. "maxw": "250px", "zoom": "1.25", — maxw is how wide the remote may draw, zoom scales all of it at once: buttons, their icons and labels, the gaps, the d‑pad and the rockers. maxw is measured before the zoom, so it grows too — halve one to hold the width while the buttons get bigger.
A button is its action name, or ["spare1","Netflix"] to label it — pair that with an override on the same host and the key both reads and does what you want — or ["spare1","Netflix","#e50914 wide"] to colour and size it (light sm md lg xl wide sq squircle, or fill h:80 for rectangles that share their row's width). Add icon: and a name among those options to put an icon from Button Icons on the key — ["spare1","Netflix","icon:netflix lg sq"], with ih:36 to draw it larger or smaller than the key's size gives it — and its label becomes the tooltip, and what the key shows if the icon is missing. theme is optional, and its bg takes a gradient.
Put a logo on a key. Paste the text of a logo's .svg file — open the file in Notepad and copy all of it, from <svg to </svg> — or drag the file onto the box. Give it a name and Import: it is turned into plain shapes in this browser and stored on the keyboard. Then any style can use it: ["spare1","Netflix","icon:netflix lg sq"]. lg sq gives the logo a bigger, squarer key; wide suits a long wordmark. Style 6 is a ready example — pick it under Remote Style and Export it to see the syntax. Exporting a style takes its icons along, so a style pasted into the Home Assistant card draws them too.
The key this host handed over when it paired. Phones advertise a random address that changes every few minutes, and this is the only thing that can tell you a given random address belongs to this host — which is what presence detection needs. Take it to Home Assistant's Private BLE Device integration, or a second ESP32 running esp32_ble_tracker. It can't be done on this device: that component and this one both need to own the Bluetooth controller.
Treat this like a password. Anyone holding it can follow that device's random address for as long as the pairing lasts. Don't post it in an issue or a forum thread.
